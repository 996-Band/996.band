# 996 Band 内容后台使用手册

这份手册写给一起维护官网的乐队成员。日常新增相册、公告、文章、专辑或单曲，不需要
修改代码，也不需要手写配置文件。

## 先记住四件事

1. **开始前先同步最新代码。**
2. **后台保存只会修改本机文件，不会自动发布。**
3. **修改后先预览，再点击“检查并构建”。**
4. **不要把 `.env`、OSS 密钥或账号密码提交到 GitHub。**

## 一、第一次使用

第一次配置只需要做一次。如果电脑已经能运行本项目，可以跳到“二、每次维护网站”。

### 1. 获取项目

推荐普通成员安装 [GitHub Desktop](https://desktop.github.com/)，登录自己的 GitHub
账号，然后 Clone：

```text
https://github.com/996-Band/996.band
```

项目的新版分支是 `site-v2`。

### 2. 安装运行环境

需要安装：

- Node.js 22
- pnpm 11.7.0

安装 Node.js 后，可以在终端执行：

```bash
npm install -g pnpm@11.7.0
```

进入项目目录，安装项目依赖：

```bash
pnpm install
```

### 3. 判断自己是否需要 OSS 权限

| 维护内容 | 是否需要 OSS 配置 |
| --- | --- |
| 只改公告、文章文字 | 不需要 |
| 只改现有相册名称、日期、简介、顺序 | 不需要 |
| 新增相册图片、追加图片、更换专辑封面 | 需要 |

需要上传图片的成员，请向网站管理员申请**个人专用、最小权限的阿里云 RAM 凭证**。
不要多人共用主账号 AccessKey，也不要把凭证发到群聊。

管理员会协助把 `.env.example` 复制为 `.env` 并填写本机配置。`.env` 只保存在个人电脑，
Git 已经默认忽略它。

## 二、每次维护网站

### 第 1 步：同步最新版本

在 GitHub Desktop 中：

1. 选择 `996.band` 仓库。
2. 切换到 `site-v2`。
3. 点击 **Fetch origin**。
4. 如果出现 **Pull origin**，继续点击它。
5. 基于最新 `site-v2` 新建分支，例如：
   - `content/notice-d2`
   - `content/photos-2026-live`
   - `content/article-new-song`

一项内容更新使用一个分支，完成后通过 Pull Request 合并，可以明显减少多人修改冲突。

### 第 2 步：打开两个终端

终端 A 启动内容后台：

```bash
pnpm content:manage
```

浏览器会打开：

```text
http://127.0.0.1:4310
```

终端 B 启动网站预览：

```bash
pnpm dev
```

网站预览地址：

```text
http://127.0.0.1:4321
```

后台和网站是两个不同的页面。后台负责修改内容，网站负责查看最终效果。

### 第 3 步：修改并保存

后台左侧有四个区域：

- **PHOTOS**：相册和图片。
- **NOTICE**：演出、发布和网站公告。
- **ARTICLES**：文章与乐队故事。
- **ALBUMS**：专辑和单曲。

点击左侧已有内容可以编辑；点击列表右上角的 `＋` 可以新增。

### 第 4 步：检查效果

1. 回到 `http://127.0.0.1:4321` 查看首页。
2. 检查电脑宽度和手机窄屏宽度。
3. 点击新增的链接，确认文章、相册和站外地址能打开。
4. 回到后台，点击右上角 **检查并构建**。
5. 看到“构建通过，可以预览或提交”后再进入下一步。

### 第 5 步：提交并发布

内容后台不会自动操作 GitHub。在 GitHub Desktop 中：

1. 查看 **Changes**，确认没有 `.env` 或无关文件。
2. 填写简短说明，例如 `content: add 2026 live photos`。
3. 点击 **Commit to content/...**。
4. 点击 **Push origin**。
5. 点击 **Create Pull Request**，目标分支选择 `site-v2`。
6. 请另一位成员简单确认后合并。

内容合并到 `site-v2` 后，GitHub Actions 会自动检查并发布网站。

## 三、维护 PHOTOS 相册

### 新增一组相册

提前准备一个照片文件夹，建议先把文件名排好：

```text
01.jpg
02.jpg
03.jpg
...
```

后台会按文件名自然排序。常用格式支持 JPG、PNG、WebP、HEIC、MP4 和 MOV；包含视频时
电脑还需要安装 FFmpeg。

操作步骤：

1. 进入 **PHOTOS**。
2. 点击 `＋`。
3. 填写相册名称、Slug、日期、地点和一句话简介。
4. 点击“选择照片文件夹”并选择准备好的目录。
5. 选择封面。
6. 点击 **创建并保存**。
7. 等待图片优化、OSS 上传和网站构建全部完成。

系统会自动：

- 修正照片方向。
- 生成最长边不超过 1920px 的 WebP 大图。
- 生成最长边不超过 720px 的 WebP 缩略图。
- 为视频生成 MP4、封面和缩略图。
- 生成相册配置和媒体清单。
- 在已启用 OSS 模式时先上传并校验 CDN，再写入正式内容。

请继续保留自己的原始照片文件夹。网站仓库保存的是优化后的网页版本，不代替原片备份。

### 修改已有相册

选择一组相册后，可以：

- 修改名称、日期、地点和简介。
- 点击 `C` 设置封面。
- 点击 `←`、`→` 调整顺序。
- 点击 `×` 移除图片。
- 点击“＋ 添加单张图片”追加照片。

调整完成后必须点击 **保存修改**。相册至少需要保留一张素材，Slug 创建后不能修改。

### 删除相册

点击相册编辑页右上角 **删除**，确认后会删除：

- 这组相册的内容配置。
- 仓库中的优化图片。

不会删除你电脑上原始照片文件夹。OSS 上已经失去引用的旧对象不会立即删除，会保留一段
时间后由管理员统一清理，防止缓存中的旧页面突然失效。

### 首页相册排序

相册按“日期”从新到旧排序，首页展示最新 9 组。要让一组相册排到前面，请填写正确日期，
不要靠修改文件名控制顺序。

## 四、维护 NOTICE 公告

### 新增公告

1. 进入 **NOTICE**。
2. 点击 `＋`。
3. 填写标题、Slug、类型、日期、链接和摘要。
4. 勾选“当前启用”。
5. 点击 **创建并保存**。

字段说明：

- **开始日期**：到这一天才会显示。
- **结束日期**：超过这一天自动隐藏；长期公告可以留空。
- **优先级**：数字越大越靠前。
- **跳转链接**：站内文章使用 `/articles/文章-slug`，相册可以使用 `/photos`，站外地址
  需要填写完整的 `https://...`。
- **当前启用**：取消勾选后立即退出首页候选列表。

首页最多取优先级最高的 3 条有效公告。手机端会优先完整展示第一条，第二条只使用剩余
空间，所以最重要的公告应设置最高优先级。

## 五、维护 ARTICLES 文章

### 新增文章

1. 进入 **ARTICLES**。
2. 点击 `＋`。
3. 填写标题、Slug、发布日期、标签和摘要。
4. 在“正文”中使用 Markdown 写文章。
5. 未完成时勾选“保存为草稿”。
6. 点击 **创建并保存**。

发布后的文章地址为：

```text
https://996.band/articles/你的-slug
```

例如 Slug 是 `new-song-story`，地址就是：

```text
https://996.band/articles/new-song-story
```

草稿不会出现在首页、文章列表，也不会生成可访问的详情页。正式发布前需要取消草稿状态。

常用 Markdown：

```markdown
## 二级标题

这是一段正文。

- 列表一
- 列表二

[链接文字](https://example.com)

> 这是一段引用。
```

首页按发布日期从新到旧展示最新 3 篇非草稿文章。

## 六、维护 ALBUMS 专辑与单曲

1. 进入 **ALBUMS**。
2. 点击 `＋`。
3. 填写名称、Slug、类型、发行日期、站外链接和简介。
4. 选择封面图片。
5. 勾选“在首页启用”。
6. 点击 **创建并保存**。

类型可以选择：

- `SINGLE`：单曲。
- `EP`：EP。
- `ALBUM`：专辑。

“首页优先级”数字越大越靠前。首页只显示已启用内容，并取优先级最高的 4 项。
封面会自动转换为 WebP；更换封面时不选择新文件会保留原封面。

## 七、Slug 怎么填

Slug 是内容的稳定编号，也会成为文件名或网址的一部分。

正确示例：

```text
d2-2026
new-song-story
album-01
```

规则：

- 只使用小写英文字母、数字和连字符 `-`。
- 不要使用中文、空格、下划线或大写字母。
- 创建后不可直接修改。
- 同一类内容不能使用重复 Slug。
- 公告配置的 Slug、文件名和后台记录会自动保持一致。

## 八、团队协作与权限

### 推荐分工

- **文字维护者**：公告、文章、已有内容文字；不需要 OSS 密钥。
- **媒体维护者**：新增相册、追加图片、更换封面；需要个人 RAM 凭证。
- **发布维护者**：审核 Pull Request、检查 GitHub Actions 和线上结果。

### 避免冲突

- 每次开始前先 Pull。
- 每项更新创建独立分支。
- 不要两个人同时编辑同一篇文章或同一组相册。
- Pull Request 尽量小，一次只处理一件事。
- 如果 GitHub Desktop 显示冲突，不要随便选择覆盖，先联系网站管理员一起处理。

### 凭证安全

- `.env` 永远不提交。
- 不分享 `OSS_ACCESS_KEY_SECRET`、STS Token 或主账号密钥。
- 每位媒体维护者使用独立 RAM 身份，离开维护工作后可以单独停用。
- `oss-browser2` 用于查看、抽查和紧急下载，不作为日常内容发布入口。

## 九、常见问题

### 保存文章后访问 404

依次检查：

1. 是否仍勾选“保存为草稿”。
2. 网址是否与 Slug 完全一致。
3. 是否运行着 `pnpm dev`。
4. 后台“检查并构建”是否通过。

### 首页没有显示新公告

检查“当前启用”、开始日期、结束日期和优先级。未来日期的公告不会提前显示，过期公告
也会自动隐藏。

### 首页没有显示新专辑

检查“在首页启用”和首页优先级。首页只取前 4 项。

### 新相册没有排在前面

相册按日期倒序，不按创建时间排序。检查相册日期。

### 图片上传失败

检查：

- 本机 `.env` 是否配置。
- 后台顶部是否显示 `OSS CDN`。
- 是否获得个人 RAM 上传权限。
- 网络是否可以访问 OSS/CDN。
- 图片格式是否受支持。

不要为了解决上传问题把密钥写进代码或提交到 GitHub。

### 视频处理失败

安装 FFmpeg 后重试：

```bash
brew install ffmpeg
```

如果这次只有照片，可以先移除视频再创建相册。

### 误删或改错内容

只要还没有提交，可以在 GitHub Desktop 的 Changes 中找到对应文件并使用
**Discard Changes**。如果已经提交或发布，不要强制覆盖历史，请创建修复提交或联系
发布维护者执行 Revert。

### 4310 或 4321 打不开

确认对应终端仍在运行：

```bash
pnpm content:manage
pnpm dev
```

关闭终端或按下 `Control + C` 会停止服务。

## 十、发布前检查清单

- [ ] 标题、日期、标点和成员名字正确。
- [ ] Slug 使用小写英文、数字和连字符。
- [ ] 首页和详情页都已预览。
- [ ] 新增链接可以正常打开。
- [ ] 手机窄屏没有明显截断或溢出。
- [ ] 图片封面、顺序和方向正确。
- [ ] 播放器没有被设置为默认自动播放。
- [ ] 后台“检查并构建”通过。
- [ ] Git Changes 中没有 `.env`、原始大文件或无关改动。
- [ ] Pull Request 目标分支是 `site-v2`。
